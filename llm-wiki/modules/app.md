# App target

The thin SwiftUI shell: menu bar label, popover, Settings, `AppState`, provider registration and notification delivery. It holds views and wiring only; parsing and business logic live in the package ([[decisions/0004-logic-in-contribusagekit-package]]).

## Spec
- **Sections:** SPEC §9.2 (responsibilities), §9.3 (concurrency), §11 (UI), §15.3 and §15.5 (project and entry point), §20 (pitfalls: Settings activation, `MenuBarExtra`, template labels, the notch, notifications, `SMAppService`)
- **Requirements:** FR-4, FR-12, FR-30 to FR-37; NFR-3, NFR-8 to NFR-10, NFR-16
- **Tasks:** T-1.1, T-1.7, T-2.7, T-3.2, T-3.5, T-3.6, T-4.6 (UI), T-5.2 to T-5.5, T-5.7, T-5.10, T-5.11
- **Path:** `App/` and `Contribusage.xcodeproj`

## Depends on
[[modules/core]], [[modules/claude-code]] and [[modules/github]]. `App/ProviderRegistration.swift` is the only place that lists providers.

## Contract
Built so far (T-1.1): a `MenuBarExtra` with a Quit item. Build settings per SPEC §15.3: `ARCHS = arm64`, macOS 14.0, warnings as errors, `SWIFT_DEFAULT_ACTOR_ISOLATION = MainActor`, generated Info.plist with `LSUIElement`, hardened runtime, ad-hoc signing. `App/` is a synchronised folder: new files join the target without project file edits ([[decisions/0014-build-and-ci-foundation]]). The popover shell (T-1.7, SPEC §11.2, §11.3): `AppState` holds one `ProviderGroupState` (descriptor plus optional limits and activity `SourceState`) per enabled provider and a GitHub `SourceState`. `Popover/SectionStateView` draws every §11.3 state around a section's content: the first load is the placeholder value `.redacted(reason: .placeholder)`, stale and failed-with-previous values are dimmed (the age sits in every section's `SectionHeader`, so stale needs no extra line), `unparseable` adds "Show raw output". A per-minute `TimelineView` in `PopoverView` sets the `now` environment value that ages and countdowns read. Provider groups sit in a `ScrollView` whose height is the groups' measured height, capped by the screen; GitHub and the footer (Refresh ⌘R, Quit ⌘Q) stay pinned. `Popover/AppState+Mock.swift` holds mock data (the GitHub mock and `GitHubSection`'s placeholder are a `ContributionCalendar` plus stats) and one preview per §11.3 row (plus a passed reset), light and dark side by side. Live wiring (T-2.7): `AppState.live()` builds the `ProviderRegistry` from `ProviderRegistration.all(time:)` (the `ClaudeCodeProvider` with `LiveProcessRunner`, the login shell from `$SHELL` or `/bin/zsh`, and the `provider.claude-code.pathOverride` default read on every resolution) and the `enabledProviders` default, which it writes back once settled (FR-2); it creates one group per enabled provider in `loading`, then starts the `RefreshCoordinator`, whose updates it applies on the main actor. `SystemConditions` turns `NSWorkspace` sleep and wake, `NWPathMonitor` and `NSProcessInfoPowerStateDidChange` into `ScheduleConditions`, which reach `update(_:)` in order through one `AsyncStream` consumer. `PopoverView.onAppear` reports the popover opening; Refresh and the limits section's Retry call `refreshNow()`; `SectionStateView` takes an optional `retry` closure and shows Retry only with one. `LimitsSection` draws the §11.4 bar (empty after a reset) and the core's window texts (`UsageWindow+Display`, hover: absolute date and time), and one VoiceOver element per window with the §11.7 label; error lines use the §13 wording with the provider's name. Settings (T-3.2, SPEC §11.6): `AppState.live()` builds the one `GitHubAccount` (Keychain service `<bundle id>.github`, FR-16; bundle id and version are force-unwrapped because the build settings always set them); the `Settings` scene whose `TabView` so far holds only `Settings/GitHubTab`: an Account section ("@login" from the `githubLogin` default, "Connected" or, while `AppState.github` is `failed(.unauthorized)`, "Token invalid or expired", and Disconnect → `disconnect`) and one token section (secure field, Connect or Replace → `GitHubAccount.connect`, which writes only after the new token validates, Return submits, a link to GitHub's token page). The tab holds UI state only; the save rule and the Keychain calls live in [[modules/github]]. Error texts come from `SourceError.message(displayName:)` in `SectionStateView.swift`, shared by the popover's `ErrorLine` and Settings (SPEC §13 wording for `unauthorized`). The popover's `SettingsButton` activates the app, then calls `openSettings` (SPEC §20): Connect GitHub without a token, Change token… in place of Retry on a 401's error line (SPEC §13). `ErrorLine` uses small controls and a multicolor warning symbol, and wraps its message to two lines. GitHub wiring (T-3.6): `AppState.live()` builds the one `GitHubAccount` and hands the coordinator a GitHub `Job` (`GitHubReport.policy`, origin `.github`, `report(now:calendar: .current)`), starting GitHub in `loading`; `connectGitHub(token:)` and `disconnectGitHub()` change the token and tell the coordinator in one call. The Settings scene gets `AppState` from the environment, and `GitHubTab` holds UI state only. GitHub's errors show Retry (`refresh()`), except a 401, which shows Change token…. The popover heatmap draws `calendar.weeks.suffix(26)` (FR-20: fixed range, no setting) through `WeekColumns`, a `Layout` that puts the days in top-aligned columns of 7 square cells sharing the proposed width and derives its height from that width (26 weeks: 11 pt cells). Hover details (heatmap cells, reset times) are `.help` tooltips; `ContribusageApp.init` registers the `NSInitialToolTipDelay` default of 200 ms, because AppKit's default wait of about 1 s felt like no tooltip at all (SPEC §11.2). The `githubInterval` setting joins the tab with T-5.2. Buttons still inert: Locate… (T-5.2). `InsightsSection` (T-6.1, FR-38, [[decisions/0023-structured-insights]]) is a collapsed disclosure group: a segmented picker per period (selected by label, bound to the period shown so a segment is always highlighted), its summary, a `Grid` of shares and the top three of each ranking with right-aligned percents, the tool's note as the title's tooltip and VoiceOver hint. The heatmap's palette, keyboard navigation and VoiceOver are T-5.11; the footer's Settings and ⋯ items come with the Settings scene and diagnostics.

## Things that bite
- `ImageRenderer` draws AppKit-backed controls (`ProgressView`, borderless buttons) as placeholders, so the limits bar is a drawn `Capsule`; that also keeps the §11.4 colours exact.
- A heatmap wider than the popover widens the `MenuBarExtra` window and clips both sides: the first live calendar (365 days, 53 columns, ~636 pt) did that. The mock and placeholder had used 182 days, which hid the width; they are now 26 full weeks. Fixed 10 pt cells then left 26 pt empty on the right. Cells sized by `aspectRatio(1, contentMode: .fit)` shrank to dots in the real window: the `MenuBarExtra` window proposes too little height, and a fit ratio takes the smaller side (`ImageRenderer` proposes unlimited height and hid it; a hosting controller asked for 360 × 0 reproduces it). Size nothing in the popover from the proposed height.
- Return in a focused `SecureField` or `TextField` fires only its `onSubmit`, never the `.keyboardShortcut(.defaultAction)` button; the default button gets Return only while no field has focus (checked with synthetic key events in a hosting view). A form that submits on Return needs both, and the submit function guards against an empty field itself.
- `xcodebuild` needs a full Xcode selected; the Command Line Tools build the package but not the app.
- `MenuBarExtra` has no "is open" signal (SPEC §20); the popover-open trigger relies on `onAppear` of the window content firing on every open, which still needs a manual check (no automated way to click the menu bar item here).
- In the `MenuBarExtra` window a `ScrollView` has no height of its own: a `ViewThatFits` over groups and a scroll view fell back to the scroll view and drew the groups at zero height once they arrived asynchronously (the mock data had hidden it). Hence the measured height.
- Foundation's duration formatting rounds under 30 s to "0 min", hence the 1 min floor in the reset text; en_US abbreviates hours as "hr", not SPEC's "h".
- SPEC §15.5 registers a `DebugFakeProvider` under `CONTRIBUSAGE_FAKE_PROVIDER`, but `FakeProvider` lives in `ContribusageTestSupport`, which is not a product and never links into the app. Decide in T-5.9 where the debug provider lives.
