# ContribusageCore

The provider-neutral heart of the package: models, provider protocols and registry, the refresh scheduler, notification planning, generic activity infrastructure, persistence and the support seams (time, processes, HTTP, Keychain, file events, paths). It knows no concrete provider and nothing about GitHub (NFR-17).

## Spec
- **Sections:** SPEC §7 (provider model), §9 (architecture), §10.1 to §10.4, §10.6, §10.7 (types, seams, persistence), §12 (refresh policy), §13 (error handling)
- **Requirements:** FR-1 to FR-5, FR-10, FR-13 to FR-15, FR-26, FR-29; NFR-4, NFR-5, NFR-14, NFR-17, NFR-18
- **Tasks:** T-1.4 to T-1.6, T-2.4, T-2.6, T-3.1 (Keychain `SecretStore`), T-3.6 (GitHub job), T-4.3, T-4.4, T-5.1 (planner), T-5.6
- **Path:** `Packages/ContribusageKit/Sources/ContribusageCore/`

## Depends on
Nothing inside the package. Every other target depends on it.

## Contract
Built so far: `ProviderID` (SPEC §10.2), encoded as its bare raw value, also as a dictionary key (`CodingKeyRepresentable`). The seams of SPEC §10.6 in `Support/`: the protocols `TimeSource`, `ProcessRunning` (with `ProcessRequest`, `ProcessResult`), `HTTPTransport`, `SecretStore` and `FileEvents`, and `AppPaths`, a struct whose `.live` root is `~/Library/Application Support/contribusage/` ([[decisions/0015-app-paths-struct]]). `FileReading` (T-4.7, SPEC §10.6) lists folders and opens or reads files; every read path of an activity source takes it as a required parameter (`TranscriptFiles`, `IncrementalJSONLReader(fileReader:)`, `HistoryStore(provider:paths:fileReader:)`), and `JSONStore.read(_:using:)` takes it without a default, so every caller chooses (the coordinator passes `LiveFileReader()` for `state.json`) ([[decisions/0025-read-roots-check-with-t-4-7]]). Live so far: `LiveFileReader` (passthrough to `FileManager` and `FileHandle`), `SystemTimeSource`, `URLSessionTransport` (ephemeral session; a non-HTTP response throws `URLError(.badServerResponse)`) `KeychainSecretStore` (T-3.1: generic passwords under the service passed to `init(service:)`, the key as account, added with `kSecAttrAccessibleAfterFirstUnlockThisDeviceOnly`; `write` updates and adds when missing, a failed call throws `KeychainSecretStore.Failure(status:)`; its test runs only with `CONTRIBUSAGE_LIVE_TESTS=1`) and `LiveProcessRunner` (T-2.4): stdin `/dev/null`, stdout and stderr read concurrently after launch, timeout sends SIGTERM and SIGKILL 2 s later and throws `SourceError.timedOut`, cancelling the caller does the same and throws `CancellationError`; a static FIFO gate lets one process run at a time across all instances (NFR-18), so callers queue rather than join. `FSEventsFileEvents` (T-4.5, FR-27): one FSEvents stream per `changes(in:debounce:)` call with file level events, the debounce passed as the stream's latency (no separate timer) and delivery on a utility serial queue; batches hold only files (`ItemIsFile`, folders are dropped) by their real path, so a root under `/var` is reported as `/private/var`; a root that does not exist yet is watched and reports once created; ending the consumer stops, invalidates and releases the stream on its own queue, so no callback runs after teardown; a stream FSEvents cannot create or start finishes at once instead of staying silent. Dropped FSEvents (`MustScanSubDirs`) are not reported: the activity source's `rescan()` on wake and popover open covers them. `Activity/IncrementalJSONLReader.swift` (T-4.3, FR-26, SPEC §8.3.5) is a value type that keeps per file its identity (device and inode from `fstat` on the open handle, so a replace between stat and read cannot mix two files), the bytes read and the pending partial line. `read(_:lines:)` hands each complete line appended since the last call, without empty lines, as `Data` to the caller's closure for the provider's decoder, streaming the file through a fixed 64 KB buffer (`read(2)`, `memchr`) so memory does not grow with the file (NFR-2, T-4.7: whole-file `readToEnd()` left its autoreleased data alive for a whole scan and the freed blocks in malloc's cache, [[research/nfr-7-transcript-scan]]); it returns an `Outcome`: `appended`, `rescanned` (read from 0 because its identity changed or it shrank below the bytes read, so the caller drops what the file contributed before) or `gone` (the file is missing; its state is dropped). A single line is held whole until its newline (a `ponytail:` note). When it throws, the caller discards the lines it got: the next read hands them over again. `Activity/HistoryStore.swift` (T-4.4, FR-29, SPEC §8.3.4) is a value type over `providers/<id>/history.json` (schema 1, frozen `ActivityDay`s oldest first). `init(provider:paths:)` loads it and throws for an unreadable or other-version file, leaving it on disk; the owner backs it up and migrates (SPEC §10.7). `merge(_:now:calendar:)` takes the provider's live days, oldest first (as `TranscriptAggregator.days()` returns them), and freezes those before the day of `now − 48 h` (a day whose end lies more than 48 h back), never replacing a day already frozen (a frozen day also hides its live count when a clock or zone change moves it back inside the last 48 h, so each day shows once), drops days before the day of `now − 364 days` (365 days with today), writes only when the frozen set changed, and returns what to show: frozen days, then live days of the last 48 h. The frozen days stay private; `merge` is the only way to read them. Persistence (SPEC §10.7) in `Persistence/JSONStore.swift`: a `PersistedFile` declares its `schemaVersion`; `JSONStore.write` stores it as the envelope `{"schemaVersion": n, "value": …}` (sorted keys) with an atomic write, creating missing folders through `JSONStore.createFolder`, the one place that makes folders under the root (owner-only `0700`; the Claude Code probe folder uses it too). `JSONStore.read` returns `nil` for a missing file and throws `PersistenceError.unsupportedSchemaVersion` for any other version without touching the file: a cache ignores the error and is overwritten on its next write, `history.json` goes to its owner's backup and migration. `JSONStore.deleteProviderData` removes `providers/<id>/` (US-12); disk I/O stays here, `AppPaths` never touches the disk ([[decisions/0015-app-paths-struct]]). Dates use `JSONEncoder`'s default (seconds since 2001 as a double), which round-trips exactly. The provider framework (SPEC §10.2 to §10.4, T-1.6) in `Providers/`: `Provider.swift` holds `ProviderDescriptor`, `ProviderCapabilities`, `TokenCategory`, `SchedulePolicy`, `ProviderAvailability` and the protocols `UsageProvider`, `LimitsSource` and `ActivitySource`, whose watching runs while its `reports()` stream is consumed ([[decisions/0016-activity-source-stream-lifetime]]); `UsageProvider.diagnostics()` returns a provider's own lines for "Copy diagnostics" (may detect, never fetches), empty by default ([[decisions/0030-provider-diagnostics-hook]]); `Reports.swift` the neutral outputs (`LimitsReport`, `UsageWindow`, `Insights` with its periods, shares and rankings ([[decisions/0023-structured-insights]]), `ActivityReport`, `ActivityDay`, `TokenCounts` (with `+=`), `DayKey`, also built from a `Date` and the `Calendar` that defines the day) and `SourceError`, whose `unsupportedPlan(note:)` lets a `fetch()` report P-10 ([[decisions/0017-unsupported-plan-source-error]]). `ProviderRegistry` is an actor: registration order is display order (FR-1, a duplicate ID traps), `enabledProviders()` applies the stored setting or, on first run, enables every provider that reports `available` (FR-2), and the caller persists the IDs it returns, and `availability(of:)` keeps `available` for the app's lifetime and re-detects anything else at most once per minute (FR-3). The registry earns its place through that caching and the first-run default, which the coordinator would otherwise repeat. Scheduling (SPEC §12, T-2.6, [[decisions/0018-refresh-coordinator-shape]]) in `Scheduling/`: `Schedule.nextRun` is the pure decision (interval clamped to the policy's bounds, 2×/4×/8× backoff capped at the maximum, doubled in Low Power Mode, `nil` while asleep or offline for a `needsNetwork` source, never earlier than 10 s after the last wake, which is also a trigger (T-5.6), `manual` replaces all that by `manualFloor`; `triggers` run a source at the first date after its last run or once its minimum interval has passed, whichever is later, if sooner than its interval, [[decisions/0019-extra-refresh-triggers]]). `RefreshCoordinator` is an actor that runs serialized passes over the enabled providers in registry order (NFR-18 by construction), maps `fetch()` failures as SPEC §13 does in one pure function, deriving the backoff count from the resulting state (`unsupportedPlan` → `notConfigured`, rechecked after 6 h; `toolNotFound` → `notConfigured(.toolNotInstalled)`; untyped errors → `providerSpecific("unexpected")`), reports each state through its `onUpdate` closure and writes every success to `state.json` (`{"limits": {"<id>": Snapshot}, "github": Snapshot}`, schema 2 since structured insights). Every polled source is a `Job<Value>` (policy, origin, fetch, `onUpdate`, trigger dates from its value) run by one generic `run` over a `Record` class kept inside the actor (T-3.6, [[decisions/0022-github-job-in-the-coordinator]]): each provider's limits become a `Job<LimitsReport>`, GitHub is the optional `Job<GitHubValue>` the app supplies, run after the providers; since the core cannot import `GitHubReport` the coordinator is generic over its value (`RefreshCoordinator<GitHubValue>`). The shared `nextRun` holds the rules: no token (`SourceError.tokenMissing` → `notConfigured(.githubTokenMissing)`) or `unauthorized` waits for `gitHubTokenChanged()` or a manual refresh, `rateLimited(until:)` runs at the reset and not earlier, and offline replaces neither (`Record.outlastsOffline`); `nextRun` treats any other source shown offline as a manual refresh, so it runs on reconnect within its floor (SPEC §12 rule 2, T-5.6); each loop step logs the next pass and Low Power Mode (SPEC §16.5); `unsupportedPlan` rechecks after 6 h (the last two through `SchedulePolicy.fixed`). `gitHubTokenChanged()` replaces GitHub's record and persists, dropping the old account's snapshot. `restore()` shows those snapshots as `Origin.cache` (FR-10) and leaves a snapshot already in memory alone, so calling `start()` again keeps fresh data `Origin.poll`; it publishes only for a source that shows no state yet, so `start()` after enabling a provider cannot turn a failure or a rejected token back into its old snapshot; `start()` restores and starts the loop; `runDue()` is one pass and returns the next due date, which the tests drive with a fake clock. Settings (T-5.2, [[decisions/0028-settings-scope-and-wiring]]): a `Job`'s `interval` closure and the coordinator's `limitsInterval(ProviderID)` read the interval settings before every scheduling decision and replace the policy's default (clamped by `Schedule`); `intervalsChanged()` reschedules at once; `resetCaches()` forgets every snapshot, keeps the notification keys, persists and runs every source. `popoverOpened()` passes `now` as a trigger to the one pass it starts; a snapshot's `resetsAt` dates are triggers too (FR-11). Notifications (T-5.1, FR-13 to FR-15, [[decisions/0027-notification-planning-in-the-coordinator]]): `Notifications/NotificationPlanner.plan(_:displayName:settings:sent:now:)` is pure; `sent` (`NotificationPlanner.Sent`) holds one `Cycle` per provider and window label: `resetsAt`, the highest threshold sent (it stands for every lower one) and `sentAt`. It keeps thresholds 50 to 99, at most 3, prunes cycles sent more than 8 days ago, skips windows past their reset, drops a cycle whose `resetsAt` differs from the window's (re-arm, plus a "has reset" note with `notifyOnReset`), and returns one note per newly crossed threshold above the cycle's, titled "<display name>: <label> at <n> %", with one identifier per window and cycle. The coordinator takes an optional `Notifications` (settings closure, delivery); a provider's limits job wraps `fetch` to plan each fetched report, so restored snapshots never reach the planner; changed cycles go to `state.json` (`notificationKeys`) before delivery and come back in `restore()`. `Providers/UsageWindow+Display.swift` holds the §11.5 and FR-11 display rules shared by the popover and the menu bar label: `isReset(at:)`, `percentText(at:)` ("23%", "<1%", "–" after a reset) and `resetText(at:width:locale:)` (weekday and time beyond 24 h, a countdown floored at 1 min, "reset, refreshing…"; `.wide` for VoiceOver). `Models/Snapshot.swift` (SPEC §10.1, T-1.7): `Snapshot`, `Origin` (`cache`, `poll`, `activity` for an activity source's reports, `github`), `SourceState`, `NotConfiguredReason`; `SourceState.snapshot` is the current or previous value the UI can show, `Snapshot.isStale(at:after:)` applies a policy's `staleAfter`; `SourceState.diagnostics` is its FR-36 line (the case, the error in full, the shown values' ISO 8601 fetch date). `Package.swift` gives a test target `resources: [.copy("Fixtures")]` with its first fixture (so far `ContribusageClaudeCodeTests` and `ContribusageGitHubTests`), read through `Bundle.module`. `ArchitectureTests` enforces NFR-17 on every `swift test` run: the core imports no other package target, every other target imports only the core ([[decisions/0014-build-and-ci-foundation]]).

## Things that bite
`createDirectory(attributes:)` sets `0700` only on folders it creates, never on existing ones; the first folder creation decides the mode of the whole tree, so the app creates folders only through `JSONStore.createFolder` (a probe that created its folder with the default `0755` before the first snapshot write once left the tree world-readable), and the bridge script (SPEC Appendix D) runs `mkdir` under `umask 077`.

`URL.path()` percent-encodes, so `Application Support` reads `Application%20Support`; compare with `path(percentEncoded: false)`.

`for await` over an `AsyncStream` ends as soon as the task is cancelled, not when the stream finishes; `LiveProcessRunner` waits for exit in an unstructured task so a cancelled caller still waits for the kill. A grandchild that keeps the output pipes open delays the result until it exits (marked `ponytail:` in the source).

Plain `swift test` lets warnings through; the AGENTS.md test command adds `-Xswiftc -warnings-as-errors`, as CI does ([[decisions/0014-build-and-ci-foundation]]).

**The coordinator cannot see GitHub.** SPEC §9.1 draws `RefreshCoordinator → GitHubService`, but NFR-17 forbids the core importing GitHub, so the app supplies GitHub as a job and the coordinator is generic over its value ([[decisions/0022-github-job-in-the-coordinator]]). A generic type holds no static stored properties, so the coordinator's constants sit at file scope.

`Task.sleep` runs on the continuous clock, so a sleep that spans the Mac's sleep fires on wake, before `didWake` may have arrived. The app must set `isAsleep` on `willSleep`; a pass that sees it schedules nothing, and the wake update restarts the loop.
